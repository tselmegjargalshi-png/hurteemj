# Хүртээмж

Монголын хөгжлийн бэрхшээлтэй хүмүүст зориулсан хүртээмжтэй платформ: туслах хэрэгслийн дэлгүүр, бичгээр тусламж, хүртээмжийн тохиргоо, админ удирдлага. Бүх интерфэйс Монгол хэл дээр, WCAG 2.2 AA зорилготой.

> **Туршилтын (MVP) хувилбар.** Юу бэлэн, юу бэлэн биш болохыг доор тодорхой бичсэн. Сайтын `/status` хуудас мөн бодит төлвийг харуулна.

## Бэлэн БИШ / холбогдоогүй

- **Онлайн төлбөр (QPay, карт): холбогдоогүй.** Захиалга үргэлж «Төлөгдөөгүй» төлөвтэй үүсч, админ дансны шилжүүлэг/бэлэн төлбөрийг гараар баталгаажуулна. Сайт хэзээ ч төлбөр амжилттай болсон мэт харуулахгүй.
- **AI туслах: нөөц горимоор л баталгаатай.** `ANTHROPIC_API_KEY` байхгүй үед зөвхөн каталогийн хайлт хийж, «AI холбогдоогүй» гэж ил хэлнэ. Түлхүүртэй үеийн Anthropic API дуудлага бичигдсэн боловч **бодитоор туршаагүй**.
- **Газрын зураг: холбогдоогүй.**
- **SMS/имэйл мэдэгдэл: холбогдоогүй** — мэдэгдэл сайт дотор бичгээр.
- **Дохионы хэлний автомат орчуулга: байхгүй** (найдваргүй тул санал болгохгүй).
- **Түрээс/хуучин бараа:** бүтээгдэхүүний хуудсанд түрээсийн үнэ, барьцаа, нөхцөл, ариутгал/аюулгүй байдлын шалгалтын мэдээлэл харагдана (нийтлэхэд заавал). Түрээсийн онлайн захиалгын урсгал **байхгүй** — «тусламжийн хүсэлт» болгон илгээнэ. Засварын үйлчилгээ нь «Үйлчилгээ» модулиар бүртгэгдэнэ.
- Үйлчилгээ, хүртээмжтэй газар, ажил, нийгэмлэг, асран хамгаалагч, дэмжлэгийн хөтөлбөр: **ажиллана** (e2e тесттэй), гэхдээ **өгөгдөл хоосон** — админ бодит мэдээллээр бөглөнө. Газрын мэдээлэл нийтлэхийн өмнө админ шалгана; хэрэглэгчийн нэмсэн газар «нийгэмлэгээс мэдээлсэн» тэмдэгтэй, нийтлэгдээгүй.
- Асран хамгаалагчийн хэсэг: сонгосон мэдээллийг (жишээ нь захиалга) зөвхөн хэрэглэгч өөрөө урьж, тусгай зөвшөөрөл өгсөн үед л харна; хэзээ ч цуцалж болно. Нарийвчилсан тест хараахан бага.
- **Бүтээгдэхүүн, үнэлгээ, үйлчилгээ үзүүлэгч, ажлын байр: өгөгдөл байхгүй.** Зохиомол зүйл үүсгээгүй; админ бодит мэдээллээр нэмнэ.
- Файл (зураг) байршуулах сан холбогдоогүй — админ одоогоор https зургийн холбоос + заавал alt тайлбар оруулна.

## Суулгах

Шаардлага: Node.js ≥ 20.9, PostgreSQL ≥ 14.

```bash
npm install
cp .env.example .env          # DATABASE_URL, ADMIN_* утгуудыг бөглөнө
npm run db:migrate            # хүснэгтүүд
npm run db:seed               # зөвхөн 14 ангилал
npm run db:create-admin       # ADMIN_EMAIL / ADMIN_PASSWORD (≥ 10 тэмдэгт)
npm run dev                   # http://localhost:3000
```

Админ нэвтэрсний дараа: **Хүргэлтийн төрөл** нэмэх (эс бөгөөс захиалга өгөх боломжгүй), **Тохиргоо**-д дансны мэдээлэл, **Бүтээгдэхүүн** нэмэх.

## Тест

```bash
npm run test:e2e   # туршилтын DB (нэрэнд "test" агуулсан) дээр build хийж Playwright + axe-core ажиллуулна
```

`TEST_DATABASE_URL` өгөөгүй бол `postgres://postgres@localhost:5432/hurteemj_test` ашиглана. Тест энэ DB-г **бүрэн цэвэрлэдэг**; нэрэнд `test` байхгүй бол ажиллахаас татгалзана. Дэлгэрэнгүй: [docs/ACCESSIBILITY.md](docs/ACCESSIBILITY.md).

## Vercel deploy

1. Vercel дээр repo-г Import хийнэ (Next.js автоматаар танигдана).
2. PostgreSQL үүсгэнэ (Neon / Supabase / Vercel Marketplace) → `DATABASE_URL` Environment Variable-д нууцаар тохируулна.
3. `APP_URL`-г production хаягаар тохируулна.
4. Анхны migration: локалаас `DATABASE_URL=<prod> npm run db:migrate && npm run db:seed && npm run db:create-admin`.
5. Нууц түлхүүрүүд (`QPAY_*`, `ANTHROPIC_API_KEY`, `MAPS_API_KEY`) зөвхөн серверийн орчны хувьсагчид; клиент кодод орохгүй.

## Аюулгүй байдал

- Админ болон хэрэглэгчийн эрхийн шалгалт сервер талд (`requireAdmin`, эзэмшлийн шалгалт — өөр хэрэглэгчийн захиалга/хүсэлт `404`).
- Нууц үг bcrypt (cost 12); session токен cookie-д (`httpOnly`, `sameSite=lax`, prod-д `secure`), DB-д зөвхөн SHA-256 хэш.
- Next.js server action-ы Origin шалгалт (CSRF), zod-оор бүх оролтын баталгаажуулалт, Drizzle (параметржүүлсэн query), React-ийн автомат escape (XSS), CSP болон аюулгүй байдлын header-үүд.
- Rate limit: нэвтрэх, бүртгэл, захиалга, тусламж, сагс (PostgreSQL дээр).
- Төлбөрийн картын мэдээлэл хадгалахгүй. Хөгжлийн бэрхшээлийн төрөл, эрүүл мэндийн мэдээлэл цуглуулдаггүй.
- Аудит лог: бүтээгдэхүүн, захиалгын төлөв, төлбөр, эрх, тохиргооны өөрчлөлт.
- Мэдэгдэж буй: `npm audit` дээр (1) `zod` 3.x-ийн high — «хэт том collection шалгахад санах ой дүүрэх». Манай схемүүд зөвхөн богино string/тоо шалгадаг, массив хүлээн авдаггүй тул шууд өртөөгүй; zod 4 руу шилжих ажил хойно (breaking change). (2) drizzle-kit → esbuild moderate — зөвхөн dev хэрэгсэл, production-д орохгүй.
